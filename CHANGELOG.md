# Accura Change Index

This root file is the concise chronological index for notable Accura changes. It does not duplicate rationale. Follow each link to the owning decision or QA record.

## 2026-11-11

- Settled `PRD-002` open question 3: a previous version becomes **Superseded when the revision is approved**, not when the new Effective Date arrives 10 days later. This is what the prototype already did, so nothing changed in code — the behaviour is now a chosen rule rather than a default. It leaves a 10-day window in which a document family has a Superseded version and an Approved-but-not-yet-effective one, and the user settled that too: **the Superseded version stays the one to follow** until its successor takes effect. That separates the two closed statuses — Superseded is a handover state with an end date, Obsolete is withdrawal. The details screen does not show it yet, which is now a backlog item. [Decision](docs/change-log/DECISIONS.md#2026-11-11---a-previous-version-is-superseded-on-approval-not-on-the-effective-date)
- **Approving now asks first.** The electronic-signature step was removed on 2026-11-10 because it had been built ahead of the requirement, and nothing took its place — so one click recorded an auditable decision, while the less consequential rejection kept a dialog. Approve now confirms, naming the document, the person it is recorded against, and the consequence: how many Reviewers are still outstanding, or the Effective Date the approval will set. A confirmation is not a signature — no credential, no identity check — so `PRD-002`'s deferral still holds; recorded as a decision because the ACs do not ask for it. Alongside it: **each prototype role is a named person** now, so switching the role switches the avatar, name and description in the top bar and the decision is recorded under that person rather than whichever slot the document had outstanding; **global search narrowed to 300px**; the **row menu lost View owner (which did nothing) and View details opens the document** instead of a dialog that summarised the row and then offered to open it; and reviewer status reads **Awaiting** rather than Pending, renamed in the data model so label and value cannot drift. [Decision](docs/change-log/DECISIONS.md#2026-11-11---approving-is-confirmed-because-the-signature-step-that-used-to-guard-it-is-gone) · [QA evidence](apps/accura-prototype/design-qa.md#iteration-48--approving-asks-first-and-the-shell-says-who-you-are)
- Brought the Draft editor back in line with the other document screens and applied a settled pattern that had never reached Documents. **Tags moved into Document Information**, where the create form and the details view already keep them — the editor was the only screen giving them a card. **Selected references** became plain rows matching the details view instead of bordered boxes. The register's **inline save banner became a toast**, which `DECISIONS.md` settled on 2026-11-04 and Settings has used since; Documents had kept its own banner, so one kind of message appeared two ways depending on the module. That exposed a collision the sticky footer created — the toast landed on the Submit button — so the toast's bottom offset clears it. **Create Document gained Cancel** for both categories, matching the Draft editor. **"None linked." no longer shows while editing**, only on a saved document. And the **prototype role switcher moved to the top bar**, beside the user it stands in for, with `ProtoRole`, `canManage` and the switcher extracted to `components/prototype-role.tsx` and the role held once instead of per screen. [QA evidence](apps/accura-prototype/design-qa.md#iteration-47--the-draft-stops-being-its-own-screen-and-a-settled-pattern-finally-reaches-documents)
- **Superseded got its own colour, and the status palette got one home.** It was the only status using the outline badge, which is the metadata treatment, so `Superseded · Controlled` in a row read as two badges of the same kind. It is now violet — Tailwind purple-100 on purple-800, 7.39:1 — chosen over amber or red because Superseded is a handover state, not a fault: the version stays in use until its successor takes effect. The register and the details view each held their own status map, both mapping Superseded to outline; there is now one map in `components/document-status.ts` and one token in `globals.css`. Also: **every count badge in the details view is gone** (they were added in Iteration 44 and removed on the user's call — on a read-only panel the items are right underneath); **six action buttons became View audit trail plus a More actions menu**, with status-gated items disabled inside it and permission-gated items absent; and the **footer is sticky in every status**, where previously it was sticky while a decision was pending and static once the document was Approved. [Rule](docs/rules/ui-hierarchy.md#badges) · [QA evidence](apps/accura-prototype/design-qa.md#iteration-46--superseded-gets-a-colour-the-action-bar-gets-a-menu-the-footer-stops-moving)
- A **Superseded document can now be cited as a reference**, at the user's direction. The mockup's rule names Draft, In Review and Approved only, but a Superseded version stays the one to follow until its successor takes effect, so a document written in that window has to be able to cite the version actually in use. Obsolete stays excluded — `US-016` AC-04 puts it beyond linking in as many words — and so does In Approval, which the mockup omits without saying why. Measured: `ACME-VMP-2026-000001 v2.0 (Superseded)` now appears in the picker; the Obsolete external certificate does not. [Decision](docs/change-log/DECISIONS.md#2026-11-11---a-superseded-document-can-be-cited-as-a-reference)
- **References can be added.** Four "Search documents to link…" fields across the create form and the Draft editor did nothing, so a reference could be removed but never created and every link on screen came from seeded data. A shared `ReferencePicker` replaces them, holding only the filters the control needs to be usable: match on ID or name, never itself, never the same document and version twice, and only the statuses the mockup allows — "Draft, In Review, or Approved", which excludes In Approval as well as the closed states. Superseded is excluded with it, which sits against the 2026-11-11 decision that a Superseded version stays usable; using a document and citing it are different acts, so the mockup is followed and the tension is flagged for the BA. Fixed alongside it: the create form was collecting tags, attachments, references, reviewers and an approver, validating them, and then **saving none of them** — `CreatedDocument` carried six fields. [QA evidence](apps/accura-prototype/design-qa.md#iteration-45--references-can-be-added-and-the-create-form-stops-dropping-what-it-collected)
- Scoped the **Add-inside-the-input** control to Tags, at the user's direction. The catalogue had generalised it to "an Add control for a free-text field sits inside the input", which would have pulled References and other pickers towards a text box with a button. It is a convenience for typing several short free-text values in a row and nothing else; a field whose value comes from a known set stays a combobox with chips. [Rule](docs/rules/ui-hierarchy.md#form-fields)
- Refine pass, second round, on the document details screen. The **stepper caption** was one hard-coded string, so every completed stage credited the Author — including Approval, whose actor is the Approver. It is derived per stage now, and where a stage can have several actors it states a count ("Approved by 2 Reviewers") rather than naming one and hiding the rest behind "+1"; the Approval card beside it already holds the names. Caption size 11px → 12px. The **Approval card groups by role** — Reviewers with an approved/total badge, then Approver — instead of a flat column where the Approver was just the last row. **Attachments and references lost their buttons**: the item's own name is the link, a reference opens the document it names, and both sections carry count badges. **Related and Referred became group headings** rather than muted captions, because the difference between what supports a document and what it cites is context, not a sub-label. The **preview gained zoom (50–200%) and a full-screen view**, since the preview column is 360px narrower than the page it renders. Finally a **capitalisation rule that cannot be misread** replaced "one screen, one casing" — group headings Title Case, value and control labels sentence case — and a sweep found the same content called *Document Details* in two screens and *Document Information* in a third; all three now read Document Information · Reference Documents · Approval. [Rule](docs/rules/ui-hierarchy.md#capitalisation) · [QA evidence](apps/accura-prototype/design-qa.md#iteration-44--the-details-panel-reads-as-content-and-one-thing-gets-one-name)
- First four items of the refine pass. The **Draft editor gets Cancel back** beside Save and Submit, running the same discard confirmation as Back to Documents — a reversal of the 2026-11-10 removal and a divergence from `US-014` AC-01, recorded as a decision: the rule guards against losing work unconfirmed, and this control cannot. **"Attachments · 0/5" lost its counter**, which read as five files to supply rather than a ceiling; the maximum moved into the section hint and the Add control stays disabled at five. **Document category → Document Category**, the only sentence-case heading on a Title Case screen. And the **Document ID now looks like the link it is**: at rest it was the same `rgb(39, 39, 42)` as the Name beside it, so it takes Brand 900 `#175e41` — a real hue shift at 7.7:1 on white — with the underline revealed on hover. [Decision](docs/change-log/DECISIONS.md#2026-11-11---a-draft-and-the-create-form-keep-a-cancel-action-guarded-by-the-discard-confirmation) · [Rule](docs/rules/ui-hierarchy.md#identifiers-and-counters) · [QA evidence](apps/accura-prototype/design-qa.md#iteration-43--first-four-of-the-refine-pass)
- Built the **last six Document-module stories** — `US-013` Approve, `US-014` Edit Draft, `US-015` Upload Revision, `US-016` Mark as Obsolete, `US-017` Print and `US-018` Download — taking PRD-002 to eleven of eleven built. The blocker under all of them was that the flow screens could change only the *view*: approving, saving or obsoleting a document took effect on screen and vanished on the way back to the register. The register now hands the screens a way to write to the record. **Approving** sets the status and the Effective Date 10 days out, and supersedes the previous version at that moment. The **Draft editor** became the Draft's own record — name, department, tags, attachments, reviewers and approver are editable, Document ID, type, author, version and status are not, Save and Submit write back, an invalid save is refused with the correction named, and leaving with unsaved edits is confirmed. **Upload Revision** requires a replacement file and a change summary, then creates the next `vN.0` as a Draft with the route reset and the source left Approved. **Mark as Obsolete** is offered only on an Approved document and confirmed with Keep document / Mark as Obsolete. **Print** is gated by status and reduces the page to the document itself through a `@media print` block. **Download** offers the original always and the controlled PDF only while Approved; since the prototype stores no uploaded bytes, both hand over a labelled placeholder and say so rather than imitating a real file. Measured end to end: an Approved document revised, reviewed, approved again, and its previous version superseded. What is deliberately thin — files are presence-only, Revision History is plain text where US-015 asks for rich text, references can be removed but not added, nothing survives a reload — is listed under Refine pass backlog in [`docs/agent-worklog.md`](docs/agent-worklog.md). [QA evidence](apps/accura-prototype/design-qa.md#iteration-42--the-last-six-stories-and-the-screens-start-changing-the-record)
- Fixed a fixture defect that `US-014`'s own validation caught: seven of the eleven sample rows had their **Author also assigned as a Reviewer**, which `US-007` AC-02 forbids. The routes are corrected.
- Built **US-012 Review Controlled Document**. The screen had let a single Approve move the document straight to In Approval; AC-02 keeps it In Review until *every* assigned Reviewer has approved. Documents now carry a **route** — a decision per assigned Reviewer plus an Approver — the Approval card is built from it instead of from two fixed names, and the tally is keyed by document so one row's decisions never leak into another's. An approval clears one assigned slot and is recorded under the acting user, annotated when a Read and Write All Records user acted for someone else; that reading of the story's note is recorded as a decision. AC-01's gate is demonstrated through a **prototype role switcher** — explicitly marked as prototype chrome, since authentication is not built — and a user without eligibility gets no action bar at all rather than a disabled one. **Reject** now answers an empty Reason instead of disabling: AC-03 asks for a prompt, so the control stays live and the field reports. The reason is finally kept: a rejected document returns to Draft with a notice naming the **rejecting role, user, date and time, and reason**, which `US-011` AC-03 also requires, and resubmitting clears it and resets the tally. Fixed two defects found on the way: the reason survived into the next rejection, because a dialog opened by state never receives Base UI's `onOpenChange(true)`; and the Draft editor was showing a literal `ACME-BR-2026-000001` with fixed name, type and department, so rejecting any document returned a Draft labelled as an unrelated Batch Record. - Settled the **workflow stepper**'s labels: the four stage names are semibold in the brand colour at every stage, not only the current one, with the caption beneath each kept muted — the names label the lifecycle, so they should not fade in and out with the document's position. Recorded as a rule, and the catalogue entry is now Ready: its open question, what the stepper shows for Superseded and Obsolete, is answered by showing none at all. [Rule](docs/rules/ui-hierarchy.md#workflow-stepper) · [QA evidence](apps/accura-prototype/design-qa.md#iteration-40--us-011-and-the-details-screen-learns-which-document-it-is-showing)
- Built **US-011 View Document Details**. The root problem was that the details screen did not know which document it was showing: opening a row routed by status and discarded the record, so every row rendered the same hard-coded sample — the preview's letterhead still named a different document than the header. The opened record is now passed through and drives the screen. Added Category (separate from Document Type, per AC-01), Document Type, and **Next Periodic Review**, derived rather than stored: a Controlled Document's approval date is its effective date less the 10 days of `US-013`, an External Document is approved at registration, and the review date is that plus the type's frequency, defaulting to three years. The stepper is hidden on closed and External documents, which are not at a current workflow stage. The side panel now carries all four of the mockup's sections — Document information, **Attachments**, **Reference documents** and Approval — with the mockup's own sample content, including references to two documents that are already rows in the register; an External Document gets neither references nor approval. All eleven sample rows carry that content, so every status demonstrates the panel; the ten beyond the mockup's own document are prototype data and are flagged as such in [`docs/agent-worklog.md`](docs/agent-worklog.md). ## 2026-11-10

- Gave the Documents register horizontal scrolling with a pinned row-action column, and settled how that column behaves. While there is more of the row to see, the action belongs to one row: it is hidden everywhere else and lifts on the row under the pointer or keyboard focus, as a white bordered chip with a shadow, over a cell that masks the columns scrolling underneath. The elevation sits on the action rather than on the cell, where a shadow spread across a full-height cell measured correctly and could not be seen. The reveal answers to `:focus-visible` rather than `:focus-within`, so closing a menu with the mouse leaves no second chip raised on a row the pointer has left, and a row whose menu is open is held in React state, since the popup is portalled out of the row and no CSS state still describes it. At the end of the row, where the actions have their own column and cover nothing, every row shows a plain action with no chip, border or shadow. The header's trailing cell is not pinned at all, so it no longer clips the last heading.
